# GitHub 협업 가이드

## 기본 원칙

- `main`은 안정 버전만 유지한다.
- `JAE`, `TAE`, `JONG`은 각자의 작업 브랜치다.
- 각자는 자기 브랜치에서만 작업한다.
- 작업이 끝나면 GitHub에서 Pull Request를 만들어 `main`에 합친다.
- 커밋 메시지는 한글로 작성한다.

## 브랜치 역할

| 브랜치 | 담당 |
| --- | --- |
| `main` | 검토가 끝난 안정 버전 |
| `JAE` | JAE 작업 브랜치 |
| `TAE` | TAE 작업 브랜치 |
| `JONG` | JONG 작업 브랜치 |

## 작업 시작 절차

먼저 [협업 작업 현황판](TEAM_TASKS.md)에서 자기 담당 작업과 완료 기준을 확인한다.

자기 브랜치로 이동한다.

```sh
git switch JAE
```

최신 내용을 받는다.

```sh
git pull
```

다른 사람은 본인 이름에 맞춰 브랜치를 바꿔 사용한다.

```sh
git switch TAE
git pull
```

```sh
git switch JONG
git pull
```

## 작업 저장 절차

변경 상태를 확인한다.

```sh
git status
```

변경 파일을 스테이징한다.

```sh
git add .
```

한글 커밋 메시지로 커밋한다.

```sh
git commit -m "기능: 몬스터 이동 개선"
```

자기 브랜치에 업로드한다.

```sh
git push
```

## Pull Request 절차

GitHub에서 Pull Request를 만든다.

- base: `main`
- compare: 자기 브랜치

예시:

- `JAE` -> `main`
- `TAE` -> `main`
- `JONG` -> `main`

Pull Request에는 다음 내용을 적는다.

- 무엇을 바꿨는지
- 어떻게 확인했는지
- 아직 부족한 점이 있는지
- [협업 작업 현황판](TEAM_TASKS.md)의 어떤 작업을 완료했는지

## 커밋 메시지 규칙

커밋 메시지는 아래 형식을 사용한다.

```txt
기능: 새로운 기능 추가
수정: 버그 수정
문서: 문서 변경
리팩터링: 코드 구조 개선
테스트: 테스트 또는 검증 코드 추가
```

예시:

```txt
기능: 자동 공격 로직 추가
수정: 경험치 획득 버그 해결
문서: Windows 실행 방법 추가
리팩터링: 무기 처리 코드 분리
테스트: 스모크 테스트 옵션 추가
```

## 충돌이 났을 때

- 당황하지 말고 어떤 파일에서 충돌이 났는지 먼저 확인한다.
- 자기 작업과 다른 사람 작업 중 무엇을 살릴지 팀원에게 확인한다.
- 충돌 해결 후 반드시 빌드와 스모크 테스트를 실행한다.
- 해결이 어려우면 Pull Request에 충돌 파일과 상황을 적는다.
